# luckyxiang-deepreport

> 多源素材 → 结构化深度分析报告（HTML），配 SVG 图表、目录导航、交互面板。独立运行，内容零幻觉。

## 概述

luckyxiang-deepreport 将多种源素材（论文、文档、代码、数据）自动整合为一份配有 SVG 图表的专业分析 HTML 报告。核心特色：6步工作流含不可跳过的事实验证步骤，确保内容零幻觉；完全独立运行，不依赖其他 skill；输出深色主题单文件 HTML，零外部依赖。

## 快速参考

| 命令 | 说明 |
|------|------|
| `/deepreport <路径>` | 完整报告（默认 standard 深度） |
| `/deepreport <路径> --depth brief` | 5节精简报告 |
| `/deepreport <路径> --depth deep` | 10节完整报告 |
| `/deepreport <路径> --auto` | 跳过大纲确认，直接生成 |
| `/deepreport <路径> --topic "主题"` | 指定报告主题 |
| `/deepreport <路径> --output report.html` | 指定输出路径 |

## 示例

```bash
# 分析一组 PDF 论文
/deepreport D:\work\claude\7部\CNN\*.pdf

# 指定主题和深度
/deepreport D:\work\claude\7部\CNN\*.pdf --topic "CNN 深度分析" --depth standard

# 分析代码项目
/deepreport src/**/*.ts --topic "项目架构分析" --depth brief

# 混合素材 + 指定输出
/deepreport data/*.json,docs/*.md --output report.html

# 自动模式（跳过确认）
/deepreport D:\work\claude\竞品分析\ --auto
```

## 能力边界

这个 skill 做一件事：**多种源素材 → 配图深度分析 HTML 报告**。

| 输入类型 | 处理方式 |
|---------|---------|
| `.pdf` | Read 工具分页读取（每次最多 20 页） |
| `.md` | Read 工具直接读取 |
| `.doc` / `.docx` | Read 工具直接读取 |
| `.py` / `.js` / `.ts` / `.java` 等 | Read + 结构分析（提取类、函数、模块关系） |
| `.json` / `.yaml` / `.csv` | Read + 结构化数据解析 |
| 目录路径 | 递归扫描所有可处理文件 |

**完全独立**，不依赖 docsummer、mdtohtml、anytomd 等任何外部 skill。

## 工作流总览

```
步骤0: 输入解析 → 识别素材类型与数量，确定报告主题
步骤1: 素材提取 → 对每个源文件精确提取关键信息（DRAFT + DENSITY）
步骤2: 结构规划 → 自动规划报告章节，生成大纲
步骤3: 内容生成 → 逐章节生成内容 + SVG 图表（严格基于素材，不外推）
步骤4: 事实验证 → 逐章回源文件核实，删除/标注无法验证的内容（不可跳过）
步骤5: 组装输出 → 单文件 HTML（深色主题 + 导航 + 交互面板 + SVG 图表）
```

## 步骤 0：输入解析

从用户命令中提取：

1. **源材料路径**（必填）：支持 glob 模式和逗号分隔多路径
2. **报告主题**（可选，`--topic`）：默认从素材内容推断
3. **输出路径**（可选，`--output`）：默认源目录下 `<主题>-深度分析.html`
4. **深度级别**（可选，`--depth`）：brief（5节精简） / standard（8节标准，默认） / deep（10节完整）
5. **自动模式**（可选，`--auto`）：跳过大纲确认，直接生成

### 文件扫描

- 如果输入是目录，递归扫描所有可处理文件
- 如果输入是 glob 模式（如 `*.pdf`），用 Glob 工具匹配
- 如果输入是逗号分隔的多路径，逐个处理
- 忽略不可处理的文件类型，列出被忽略的文件

### 素材类型识别

扫描完成后，统计各类型文件数量，确定素材类型：
- **文档为主**（PDF/MD/DOC > 50%）：标准 8 节结构
- **代码为主**（代码文件 > 50%）：增加架构设计和 API 章节
- **数据为主**（JSON/YAML/CSV > 50%）：增加数据结构和统计分析章节
- **混合型**：标准 8 节 + 按需调整

## 步骤 1：素材提取

对每个源文件执行两阶段提取。**不调用任何外部 skill，所有逻辑内嵌。**

### 阶段 1a：初稿提取

读取源文件全文后，使用 `references/prompts.md` 中的"素材提取 Prompt"提取关键信息。

### 阶段 1b：密度增强（1-2轮）

使用 `references/prompts.md` 中的"密度增强 Prompt"识别遗漏。

### 输出格式

每源文件一份**素材卡片**（≤600字）：

```markdown
## 素材卡片：{文件名}

- **类型**：{文档/代码/数据}
- **核心主题**：{一句话}
- **关键数据点**：
  1. {数据点1}（来源：{原文位置}）
  2. {数据点2}（来源：{原文位置}）
  ...
- **核心结论**：
  1. {结论1}
  2. {结论2}
  ...
- **关键术语**：
  - {术语1}：{定义}
  ...
- **因果关系**：
  - {因} → {果}
  ...
- **与其他素材的关系**：{引用/对比/演进}
- **可视化建议**：{适合画什么图}
```

### PDF 文件处理

PDF 文件用 Read 工具分页读取：
- 第一轮：读取前 5 页，提取标题、作者、摘要
- 后续轮：每次读取 20 页，直到读完
- 如果 PDF 是扫描件（无文字层），在素材卡片中标注 `[扫描件，无法提取文字]`，基于已有知识生成标注为 `[非原文内容]` 的补充信息

### 代码文件处理

对代码文件，提取：
- 模块/文件结构
- 类定义和继承关系
- 关键函数签名和功能
- 依赖关系（import）
- 配置和常量
- 注释中的关键说明

## 步骤 2：结构规划

基于素材卡片集合，自动规划报告章节。

### 标准 8 节结构

| # | 章节 | 内容 | 必配图表 |
|---|------|------|---------|
| 1 | 总览与脉络 | 定义、演进/背景、核心价值 | 时间线 SVG |
| 2 | 核心原理 | 关键概念、基础机制、数学直觉 | 原理示意图 SVG |
| 3 | 完整流程 | 端到端数据流、每步变化 | 流程图 SVG |
| 4 | 模块详解 | 每个核心模块的作用、原理、变体 | 结构图 SVG |
| 5 | 框架/实现详解 | 主要方案对比、架构细节 | 架构图 + 折叠面板 |
| 6 | 场景应用 | 典型应用场景、实战案例 | 应用卡片 |
| 7 | 难点与解决方案 | 常见问题、经典解决方案 | 对比表格 |
| 8 | 优劣势与展望 | 横向对比、局限性、未来方向 | 对比表格 |

### 动态调整

| 条件 | 调整 |
|------|------|
| 源文件 < 3 个 | 合并第 4、5 节为"模块与框架" |
| 源文件 > 10 个 | 第 5 节按类别拆分为多节 |
| 代码为主 | 增加"架构设计"和"API 接口"章节 |
| 数据为主 | 增加"数据结构"和"统计分析"章节 |
| depth: brief | 仅保留 1/2/3/5/8 五节 |
| depth: deep | 增加"数学推导"和"实验复现"章节 |

### 大纲输出

生成大纲后，除非 `--auto` 模式，否则展示给用户确认：

```
报告大纲：{主题}
1. 总览与脉络 — ...
2. 核心原理 — ...
   2.1 ...
   2.2 ...
3. 完整流程 — ...
...
预计 SVG 图表：{N} 个
预计总字数：{估算}
```

## 步骤 3：内容生成

**核心原则：只说素材中有的，不编造、不外推。**

逐章节生成内容。

### 内容生成约束

使用 `references/prompts.md` 中的"内容生成约束"（7条规则）。

### 生成顺序

按章节顺序生成，每章节：
1. 先写正文内容（基于素材卡片整合）
2. 再画 SVG 图表（根据 `references/svg-guide.md` 中的模板）
3. 最后加数据表格和交互元素

### SVG 图表生成

根据 `references/svg-guide.md` 中的 6 类模板生成：
1. **时间线图**：第 1 节演进脉络
2. **原理示意图**：第 2 节核心原理
3. **流程图**：第 3 节完整流程
4. **结构图**：第 4 节模块详解
5. **架构图**：第 5 节框架详解
6. **对比图/关系图**：第 7、8 节

每个 SVG 严格遵循 `references/svg-guide.md` 的配色和设计规则。

### 通俗化原则

- 每个核心概念先用**类比**解释，再给精确定义
- 类比用日常生活场景（侦探、放大镜、流水线等）
- 技术术语首次出现时加括号解释
- 公式后紧跟文字解读

## 步骤 4：事实验证（不可跳过）

**这是确保内容正确性的关键步骤。绝不跳过。**

对步骤 3 生成的每章节内容执行验证。使用 `references/prompts.md` 中的"事实验证 Prompt"。

### 验证规则

1. **数值验证**：所有百分比、参数量、错误率等数字必须与原文完全一致
2. **结论验证**：因果关系和性能比较必须有原文支持
3. **图表验证**：SVG 中的标注数据必须与正文验证后的数据一致
4. **引用验证**：引用的论文名、作者名、年份必须准确
5. **范围验证**：如果原文说"在某些情况下"，报告中不能说"总是"

### 验证后处理

- 删除所有 UNVERIFIED 和 CONTRADICTED 的内容
- 修正 PARTIALLY_VERIFIED 的内容
- 如果删除导致某段落空洞，用 `[原文未提供此方面信息]` 标注，不编造填充
- SVG 图表中的数据同步修正

### 章节结构

每个章节按 `references/report-schema.md` 中的 HTML 结构生成：
- Section 容器 + 数字编号标题
- Subsection 子章节
- SVG 图表用 `.svg-wrap` 容器
- 数据表格用 `.table-wrap` 容器
- 框架详解用折叠面板
- 优劣势用 `.pros-cons` 双栏布局

### 输出规范

- 所有 CSS + JS + SVG 内嵌，零外部依赖
- UTF-8 编码，`lang="zh-CN"`
- 文件写入 `--output` 指定路径或默认路径

## 异常处理

| 场景 | 处理 |
|------|------|
| 文件不存在 | 立即报错，给出正确路径建议 |
| 文件无法读取 | 报告已读内容，标记不可读部分 |
| 扫描 PDF（无文字层） | 标注 `[扫描件]`，基于有限信息生成 |
| 素材严重不足 | 降低深度级别，标注素材不足的章节 |
| 单一源文件 | 合并模块详解和框架详解 |
| 源文件过多（>20） | 建议用户缩小范围或使用 deep 级别 |

## 核心提醒

- **零幻觉**：步骤 4 事实验证不可跳过，逐条核实关键声明，删除无法验证的内容。
- **正确性优先**：宁可标注"原文未提及"，也绝不编造。不怕内容少，怕内容错。
- **完全独立**：不调用 docsummer、mdtohtml、anytomd 等外部 skill，所有逻辑内嵌。
- **样式固定**：HTML 输出严格使用 `references/html-style.md` 中的样式系统。
- **SVG 模板化**：图表按 `references/svg-guide.md` 中的模板生成，确保视觉一致性。
