# Skill 质量检查清单

基于 howskill 5 维度评估标准，在创建 skill 过程中实时对照检查。

## 维度 1：content_structure（权重 30%）

### Frontmatter 检查

- [ ] name 字段完整（格式：luckyxiang-{skill-name}）
- [ ] description 字段完整且 ≥ 150 字符
- [ ] version 字段存在（"1.0"）
- [ ] tags 字段存在（2-5 个）

### 必须包含的章节

- [ ] **概述** — 一段话说明 skill 做什么、核心特色
- [ ] **快速参考** — 命令表（命令 + 说明）
- [ ] **示例** — 3-5 个使用示例（代码块）
- [ ] **工作流/步骤** — 分步骤说明执行流程
- [ ] **能力边界** — 输入类型表 + 独立性声明
- [ ] **异常处理** — 场景 + 处理方式表

### 结构要求

- [ ] 至少 1 个代码块（示例）
- [ ] 至少 1 个表格（快速参考/能力边界/异常处理）
- [ ] 章节标题清晰，层级不超过 3 级

### 常见扣分项

- 缺少"用法/快速参考"章节（-0.1）
- 缺少示例代码块
- 缺少表格

## 维度 2：trigger_design（权重 25%）

### 必须包含

- [ ] **USE FOR** 触发词（≥ 3 个短语）
- [ ] **DO NOT USE FOR** 反触发词（≥ 2 个短语）
- [ ] 补充触发说明（"即使用户只是说...也应触发"）

### 触发词设计原则

- 触发词应覆盖用户可能的各种表述方式
- 包含中文触发词（用户主要用中文）
- 包含 skill 命令名作为触发词
- 反触发词应明确指向替代 skill

### 常见扣分项

- 触发词 < 3 个（-0.05 per 缺失）
- 缺少 DO NOT USE FOR（-0.05）
- 缺少使用边界声明（-0.05）

## 维度 3：user_experience（权重 20%）

### 必须满足

- [ ] description 长度 ≥ 300 字符
- [ ] 用途说明清晰（包含 USE FOR 或用途描述）
- [ ] 包含工作流/步骤指引
- [ ] 包含决策点/条件分支说明
- [ ] 包含充分的示例（≥ 3 个）
- [ ] 包含明确的"不适用场景"说明
- [ ] 内容结构清晰（≥ 20 个标题段落）
- [ ] 包含目录/导航结构

### 常见扣分项

- description 太短（< 300 字符）
- 缺少工作流指引
- 缺少"不适用场景"说明

## 维度 4：security（权重 10%）

### 必须检查

- [ ] 无硬编码密钥或敏感信息
- [ ] 无注入风险模式（eval、exec、未转义用户输入）
- [ ] 无危险操作模式（rm -rf、force push 等）
- [ ] 无硬编码绝对路径（用相对路径或变量代替）

### 常见扣分项

- 硬编码绝对路径（-0.05 per 路径）
- 缺少使用边界声明（-0.05）

## 维度 5：token_budget（权重 15%）

### 预算要求

- [ ] SKILL.md ≤ 500 行
- [ ] 预估 token ≤ 3000
- [ ] body 占比合理（不超过总 token 的 80%）

### 优化策略

- 详细内容移至 references/ 文件
- 避免大段重复说明
- 表格优于长段落
- 代码示例精简（3-5 行即可）

### 常见扣分项

- body 占比过大（-0.05）
- SKILL.md 行数过多

## 维度 5：token_budget（权重 15%）

生成 SKILL.md 后，回答以下问题：

1. description 是否 ≥ 300 字符？ → 不够则扩展
2. USE FOR 是否 ≥ 3 个触发词？ → 不够则补充
3. DO NOT USE FOR 是否 ≥ 2 个？ → 不够则补充
4. 是否有概述、快速参考、示例、工作流、异常处理？ → 缺则添加
5. 是否有代码块和表格？ → 缺则添加
6. 是否有硬编码路径？ → 有则替换
7. SKILL.md 是否 ≤ 500 行？ → 超则移内容到 references/
8. references/ 是否需要？ → 需要则创建
