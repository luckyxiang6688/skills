# 需求采访模板

## 5 个核心问题

### 问题 1：这个 skill 做什么？

**目的**：确定 skill 的核心功能和一句话描述。

**提问方式**：
- "这个 skill 主要做什么？用一句话描述。"

**提取内容**：
- description 第 1 句话
- skill 命名依据

**充分性判断**：用户回答包含动词（生成/分析/转换/检查/...）+ 宾语（报告/代码/格式/...）

---

### 问题 2：什么时候应该触发？

**目的**：确定 USE FOR 触发词列表。

**提问方式**：
- "用户说什么话的时候应该触发这个 skill？列出 3-5 个触发词。"

**提取内容**：
- USE FOR 触发短语（至少 3 个）
- 补充触发说明（"即使用户只是说...也应触发"）

**充分性判断**：至少 3 个触发短语

**默认值**：如果用户说"你看着办"，从问题 1 的回答中提取关键词生成触发词

---

### 问题 3：什么时候不该触发？

**目的**：确定 DO NOT USE FOR 反触发词列表。

**提问方式**：
- "什么情况下不应该触发这个 skill？有没有其他 skill 更适合的场景？"

**提取内容**：
- DO NOT USE FOR 反触发短语（至少 2 个）
- 与其他 skill 的边界划分

**充分性判断**：至少 2 个反触发短语

**默认值**：如果用户说"没有"，根据 skill 类型添加通用反触发词：
- content_creation: "简单概念解释、文档摘要（用 docsummer）"
- analysis: "写文章（用 writer）、生成报告（用 deepreport）"
- workflow: "深度分析（用 deepreport）、写文章（用 writer）"
- utility: "创建内容（用 writer）、分析（用 deepreport）"

---

### 问题 4：输入是什么？输出是什么？

**目的**：确定能力边界。

**提问方式**：
- "这个 skill 接受什么输入？输出什么格式？"

**提取内容**：
- 输入类型列表（pdf/md/docx/代码/json/...）
- 输出格式（HTML/MD/JSON/代码/...）
- 能力边界章节内容

**充分性判断**：至少 1 种输入 + 1 种输出

---

### 问题 5：有没有参考的现有 skill？

**目的**：确定工作流步骤模板。

**提问方式**：
- "有没有现成的 skill 可以参考？或者你希望工作流包含哪些步骤？"

**提取内容**：
- 参考 skill 路径（如提供，读取其 SKILL.md 提取工作流）
- 或用户自定义的工作流步骤

**充分性判断**：有参考 skill 或用户描述了 ≥ 2 个工作流步骤

**默认值**：如果用户说"没有"，使用对应类型的默认工作流模板

---

## 采访流程

1. 一次性检查用户原始输入是否包含所有 5 个要素
2. 如果全部包含 → 跳过采访，直接进入步骤 2
3. 如果部分包含 → 只追问缺失的要素，最多 2 轮
4. 如果完全不包含 → 按顺序逐个提问，最多 2 轮

## 信息提取规则

- 触发词从用户描述中提取动词短语和关键词
- 反触发词从"不要"/"不是"/"不用"等否定词后提取
- 输入类型从文件扩展名或格式描述中提取
- 输出格式从"生成"/"输出"/"转为"等词后提取
