luckyxiang-docsummer

万物皆可总结：PDF、Word、PPT、Markdown……CoD 密度迭代 + CoVe 事实验证，零幻觉。

这是什么

一个 Claude Code Skill，专门对文档进行高精度结构化总结。支持 PDF、Word、PPT、Markdown 等格式，输出 MD + HTML 双格式。

核心设计理念：总结的准确性不靠 LLM 的推理能力，靠 prompt 的结构化约束。借鉴学术论文中的 Chain-of-Density（密度迭代）和 Chain-of-Verification（事实验证）框架，通过多轮迭代确保信息完整、通过逐条验证确保内容准确。

支持的文件格式

格式 预处理方式
.md 直接读取
.pdf Claude Code 原生读取（分页支持）

.ppt / .pptx 复用 anytomd 转为 MD
其他格式 复用 anytomd 转为 MD

3 步 Prompt 流程

传统总结是”一次生成就结束”，信息遗漏和编造都无法修正。docsummer 采用 3 步迭代流程：

步骤 1：DRAFT — 生成初稿

基于文档内容，按用户指定的精度级别生成结构化初稿。初稿允许信息稀疏——这是 Chain-of-Density 的起点，不是终点。

短文档（≤8000字）单次生成；长文档（>8000字）自动切换分层模式：全局扫描 → 分块精读 → 整合。

步骤 2：DENSITY — 密度迭代

对比初稿与原文，识别”缺失的关键实体”，在同等长度内融入。关键实体的定义来自 CoD 论文：

  • Relevant：与文档核心论点直接相关
  • Specific：具体的数据、名称、日期、结论（不是泛泛描述）
  • Novel：当前总结中未出现的
  • Faithful：原文中确实存在的（不是推断的）

每轮迭代用具体信息替换模糊描述，而非追加新段落。重复 2-3 轮直到无重要缺失实体。

步骤 3：VERIFY — 事实验证

从密度增强版中提取所有关键声明，回到原文逐条核实。每个声明被分类为：

验证结果 处理
VERIFIED 原文明确支持 → 保留
PARTIALLY_VERIFIED 原文部分支持 → 修正
UNVERIFIED 原文中找不到 → 删除
CONTRADICTED 原文内容矛盾 → 修正或删除

只有通过验证的内容才会出现在最终总结中。

4 级精度

级别 目标字数 输出结构 适用场景
brief 300-500字 1-2段纯文本 快速了解文档大意
medium 800-1500字 3-5个标题节 常规文档总结
long 2000-4000字 两级标题层级 详细理解文档内容
deep 不限 全局概览→章节详解→数据表→引述 深度研究/长文档

deep 级别的输出结构

deep 不是”更长的总结”，而是分层结构化输出：

全局概览（文档类型、核心论点、关键方法、主要结论）
  ↓
章节详解（每章：核心命题 + 关键论据 + 重要数据）
  ↓
关键数据汇总表（数据项 | 数值 | 出处）
  ↓
核心引述（原文精确文字 + 出处位置）
  ↓
术语表（术语 | 原文 | 释义）

英文文档处理

自动检测文档语言。英文文档的总结规则：

  • 输出使用中文
  • 关键术语保留英文原文，括号附中文释义
  • 示例："该模型采用 Transformer（变换器）架构"
  • 专业术语首次出现时附英文，后续使用中文

反幻觉协议

6 条硬约束，按优先级排列：

  1. 忠实约束：所有内容必须源自文档原文，绝不添加原文没有的信息、推断或评价
  2. 精确约束：数据（数字、比例、日期）必须与原文完全一致，不可近似或替换
  3. 结构约束：输出结构必须符合指定级别，不自行创造分类框架
  4. 语言约束：英文文档保留关键术语原文（括号附中文释义）
  5. 长度约束：宁可精简也不凑字数，目标字数是上限不是下限
  6. 不确定约束：原文模糊或矛盾处标注 [原文表述不清]，而非自行解释

输出格式

每次总结产出两个文件：

  • MD 文件：<文件名>-summary.md，方便后续编辑和衔接其他 skill
  • HTML 文件：<文件名>-summary.html，浏览器直接打开阅读

HTML 主题根据精度级别自动选择：

精度级别 HTML 主题 风格
brief reading Medium 极简
medium article Tufte 风
long article Tufte 风
deep interactive 长文档导航+目录+折叠
